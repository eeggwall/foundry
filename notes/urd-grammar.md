# The URD grammar

Project Euler 502 asks for the number of *castles*: stacks of unit-height
blocks on a `w × h` grid that are fully supported, never touch on the same row,
reach height exactly `h`, and use an even number of blocks.  Counting them is
hopeless by brute force, so the first job is to find a representation that
turns the castle rules into something we can reason about.  The one that
unlocks everything is a string of `U`, `R`, and `D` steps.

## The step string

Read the skyline of a castle as a lattice path:

* `U` — up one row
* `R` — right one column
* `D` — down one row

Every castle is written `U (tower) D`.  The leading `U` and trailing `D` are
the **baseline block** (the block of width `w` that fills the bottom row); the
interior is the **tower** — the skyline above the base, read left to right.

Take a base of length 3, put a width-1 sub-block in column 1 and another in
column 3, and leave column 2 empty:

```
#.#
###
```

The tower skyline above the base is the word `URDRURD`, and the full castle is

```
U URDRURD D  →  UURDRURDD
```

![the two-sub-block castle](figures/urdrurd.svg)

The tower word records the skyline's heights measured from the top of the base
— `0, 1, 1, 0, 0, 1, 1, 0` — up onto the first sub-block, across it, off it,
right across the gap, up, across, off the second.

A width-1 sub-block that carries another width-1 block on top has tower word
`UURDD` (the interior `V` of the peak is `URD`); as a full castle it is
`UUURDDD`:

```
#
#
#
```

![stacked width-1 blocks](figures/uurd.svg)

## The grammar

Towers of height at most `k` are generated by the grammar

```
E_k -> empty | R E_k | U V D (empty | R E_k)      V = E_{k-1}, V nonempty
```

Reading the three alternatives:

* `empty` — nothing above the base;
* `R E_k` — one empty column, then the rest;
* `U V D (empty | R E_k)` — a **peak**: up onto a sub-block, the sub-tower `V`
  sitting on it, down off it, then stop or a gap column and the next peak.

`V` is one row lower because the sub-block itself uses a row, and `V` nonempty
is what keeps a sub-block from having zero width (forbidding `UD`).  The
`empty | R E_k` tail is what keeps two peaks from touching (forbidding `DU`).
This is exactly the Dyck first-return split `U w₁ D w₂` with one extra letter.

## The invariants

Everything structural falls out of the grammar:

| Invariant | Why |
|---|---|
| `#U == #D` | the path returns to the base |
| `#D == #blocks` | each `D` move completes a block |
| `#D` is even | the even-block rule (added by `validate`, not by `E_k`) |
| no `UD` | `V` nonempty forbids a zero-width block |
| no `DU` | the tail forbids two touching blocks |
| exactly `w` `R`s | one `R` per column of the base |

## Using the library

```python
>>> import castles
>>> castles.validate("UURDRURDD")          # 3 blocks — odd
ParseError('odd_blocks', 'a castle must be made from an even number of blocks')
>>> castles.validate("UURDD") is True      # 2 blocks — even
True
>>> castles.parse("UURDD").profile
(1,)
>>> castles.unparse(castles.parse("UUUURRRRRRRRDDDD"))  # 4×8 rectangle
'UUUURRRRRRRRDDDD'
>>> castles.is_tower("URDRURD")            # the interior of UURDRURDD
True
```

`validate` returns `True` or a `ParseError` with a `.reason` code
(`zero_width_block`, `touching_blocks`, `unbalanced`, `drops_below_base`,
`odd_blocks`, …).  `parse`/`unparse` are the structural bijection and ignore the
even-block rule.
